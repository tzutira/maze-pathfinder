# Границы первой версии проекта

## Цель и статус

Проект «Генератор лабиринтов и поиск пути» предназначен для наглядного изучения генерации лабиринтов и поиска маршрутов. Предполагаемые пользователи — студенты и преподаватель. Эти предположения предстоит проверить на этапе сбора требований.

Этот документ фиксирует предложение по объёму проекта для команды из трёх человек. Он не заменяет SRS. Выбор одного алгоритма генерации и одного алгоритма поиска ещё не согласован с преподавателем.

## Технологии

- Язык реализации — C++, ориентир для стандарта — C++17.
- Интерфейс — обычное консольное меню без управления мышью и анимации.
- Генерация и поиск реализуются командой самостоятельно.
- Для базовой версии достаточно стандартной библиотеки C++.
- Программа работает локально и не требует сети или сервера.

## Представление лабиринта

Лабиринт — прямоугольная сетка логических клеток. Каждая клетка имеет стены на границах с соседями. Генератор удаляет некоторые общие стены, создавая проходы. Границы с соседями должны оставаться согласованными с обеих сторон.

Высота и ширина задаются независимо: целые числа от 2 до 50 включительно. Это предложенный предел первой версии, выбранный для удобства консольной демонстрации.

Движение разрешено вверх, вниз, влево и вправо через открытый проход. Диагональных переходов нет. Каждый переход между соседними клетками имеет одинаковую стоимость — один шаг.

Координаты пользователя начинаются с 1: строка от 1 до высоты, столбец от 1 до ширины. Пользователь выбирает логические клетки, а не символы стен в консольном изображении.

Для отображения можно использовать `#` для стен, пробел для проходов, `S` для начала, `F` для конца и `*` для маршрута. Если начало и конец совпадают, клетка помечается `@`, длина пути равна нулю. Маркеры начала и конца не затираются символами маршрута.

Изображение с отдельными символами стен и проходов занимает примерно `(2 × высота + 1)` строк и `(2 × ширина + 1)` столбцов. Для защиты следует использовать небольшой лабиринт, например 10 × 10 логических клеток; большие изображения могут требовать прокрутки терминала.

## Функции первой версии

1. Ввести размеры и создать случайный лабиринт.
2. Показать лабиринт без найденного пути.
3. Указать начальную и конечную клетки; предложить по умолчанию верхнюю левую и нижнюю правую.
4. Найти путь и отобразить его с длиной в шагах.
5. Изменить выбранные точки и повторить поиск в том же лабиринте.
6. Создать новый лабиринт, очищая предыдущий маршрут и заново задавая точки.
7. Завершить работу. Некорректный ввод сопровождается понятным сообщением и возможностью повторить ввод.

## Алгоритм генерации DFS

DFS — поиск в глубину. Генератор начинает с одной клетки, помечает её посещённой и выбирает случайного непосещённого соседа. Затем убирает общую стену и переходит к этому соседу. Если непосещённых соседей больше нет, возвращается к предыдущей клетке и продолжает поиск. Для возврата планируется явный стек, чтобы не зависеть от глубины рекурсии.

Результат — связный лабиринт без циклов: между любыми двумя клетками существует ровно один простой путь. Генератор должен посетить все клетки; для N клеток будет открыто N − 1 проходов между соседними клетками.

При постоянном числе соседей время генерации — O(N), дополнительная память — O(N) для посещений и стека. Случайность меняет форму лабиринта; обещание равномерного выбора из всех возможных лабиринтов в проект не входит.

## Алгоритм поиска BFS

BFS — поиск в ширину. Поиск использует очередь и рассматривает сначала клетки на расстоянии одного шага от начала, затем двух шагов и далее. Для каждой впервые достигнутой клетки сохраняется предшественник, по которому после нахождения конца восстанавливается маршрут.

BFS находит кратчайший путь при одинаковой стоимости всех переходов. Это соответствует выбранной модели. Для N клеток и ограниченного числа соседей время и дополнительная память — O(N).

В лабиринте, полученном выбранным DFS-генератором, простой путь единственный. Поэтому DFS тоже смог бы найти этот маршрут; BFS выбран ради понятного общего алгоритма кратчайшего пути. В первой версии сравнение качества маршрутов разных алгоритмов не заявляется.

Совпадение начала и конца даёт маршрут из одной клетки и ноль шагов. Поиск должен уметь возвращать результат «пути нет», хотя при корректной генерации лабиринта все клетки связаны. Такой случай можно будет проверить на отдельно подготовленной структуре при тестировании.

## Что отложено

Графический интерфейс, анимация, ручное редактирование стен, сохранение и загрузка лабиринтов, несколько алгоритмов, A*, Kruskal, взвешенные переходы, многопоточность и сетевые функции.

Добавление циклов через дополнительные проходы возможно как будущее расширение, если потребуется сравнивать маршруты. Оно не входит в согласуемую базовую версию.

## Граница готовности реализации

Программа считается готовой к демонстрации, когда весь сценарий работает: ввод размеров → генерация → выбор точек → поиск → показ маршрута и длины → повторный поиск или новая генерация.

Корректность необходимо подтвердить проверками связности и отсутствия циклов, соблюдения стен найденным маршрутом, длины пути на небольших примерах с заранее известным ответом, совпадения точек и обработки неверного ввода.

## Распределение на трёх участников

| Участник | Основная зона будущей реализации | Вклад в документацию |
| --- | --- | --- |
| 1 | Представление лабиринта и генерация DFS | Ограничения модели, описание генерации |
| 2 | Поиск BFS, восстановление маршрута, проверки алгоритмов | Объяснение поиска и критерии корректности |
| 3 | Консольный интерфейс, отображение и объединение компонентов | Сценарии пользователя, оформление итогового документа |

На этапе требований все трое участвуют в сборе и обсуждении. SRS и UML готовятся и проверяются совместно. Перед кодированием команда согласует единое представление клеток, координат и результата поиска. Каждый участник должен понимать общий сценарий и оба алгоритма для защиты.
